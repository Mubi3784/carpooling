## Grounded findings (read from code)
- Routes today (`App.jsx`): `/` = `Feed` (Today/Tomorrow/custom date + Car/Bike filter already there; `Home.jsx` is an unused landing page whose copy says "coordinate directly on WhatsApp"), `/rides/:id`, `/road-status`, `/login`, `/register`, protected `/offer-ride /my-rides /request-ride /my-requests /requests /matches`. `main.jsx` mounts providers (Auth, Alert); read it before editing.
- `BottomNav.jsx` currently: Browse, Roads, Offer, My Rides|Login (4 items, wrong ones). `Navbar.jsx` has desktop links for everything plus a mobile scroll row "Post Request / My Requests / Passenger Requests" and an inbox icon with `useAlerts` badge. These duplicate role buttons must go.
- `AuthContext.jsx` stores whole `res.data.data.user` in `user` (login, register, `/auth/me`). Backend now returns `{id,name,role}` only. Navbar reads `user.name`, `user.role === 'admin'`.
- `AlertContext.jsx` = polling pattern (45 s, only when `document.visibilityState==='visible'`, visibilitychange listener). Copy for Chat unread.
- `Matches.jsx` (inbox): tabs All/Incoming/Outgoing via `getMatches({box})`; subtitle says "chat opens in the next update" (must change). Match view fields: `id,status(PENDING|ACCEPTED|DECLINED|CANCELLED|EXPIRED),initiatedBy,role(DRIVER|PASSENGER),direction(incoming|outgoing),passengerCount,unread,canAccept,canDecline,canCancel,counterpart{name},ride{...},request{...}`. It has NO conversation id. DECISION: "Open chat" resolves the conversation client-side by calling `getConversations()` once and mapping `conversation.matchId === match.id` (no backend change). Chat is created on accept; if no conversation is found yet, show a disabled "Chat is being set up, refresh" state.
- Backend response shapes (all wrapped `{success, data}`):
  - `GET /api/auth/profile` and `PATCH /api/auth/profile {name?, phone?}` -> `data.profile` = `{name,email,phone}`.
  - `GET /api/chat/conversations` -> `data[]`: `{id,matchId,rideId,role('DRIVER'|'PASSENGER'),otherParty{name,roleLabel},ride{pickupLocation,destination,rideDate,departureTime,vehicleType},unread,lastMessageAt,lastMessagePreview,expiresAt}`. NOTE: includes a 80-char `lastMessagePreview`; render as plain text.
  - `GET /api/chat/conversations/:id` -> `data` = same conversation view (use for thread header).
  - `GET /api/chat/conversations/:id/messages?after=<messageId|ISO>` -> `data[]` `{id,mine,body,createdAt,readAt}`; first call (no `after`) = most recent 100 oldest-first; reading marks read. 404 = not participant/missing, 410 = ended.
  - `POST /api/chat/conversations/:id/messages {body,clientMessageId}` (`clientMessageId` must match `^[A-Za-z0-9_-]{8,64}$`; a UUID with dashes is fine) -> 201 `data` message, 200 + `replayed:true` on retry; 400 invalid/empty/>500; 429 rate/limit (Retry-After header); 410 ended.
  - `POST /api/chat/messages/:id/report {reason: harassment|spam|unsafe|other, note?<=200}` -> 201, 200 `replayed:true` (already reported), 400 own message, 429.
  - `GET /api/chat/unread-count` -> `data` = `{count, unreadMessages, pendingMatches}`. DECISION: Chat tab badge uses `unreadMessages` ONLY (pending offers are already counted by the Alerts badge on the inbox); fall back to `count` never.
  - `GET /api/push/public-key` -> `data.key` (string or `null`). `POST /api/push/subscribe {endpoint, keys{p256dh,auth}}` -> 201. `DELETE /api/push/subscribe {endpoint}` (axios: `api.delete(url, { data: { endpoint } })`). Push payload from server is generic: `{title, body, data:{url}}` with url `/chat` or `/matches`.
- PWA: `vite.config.js` uses `VitePWA({ registerType:'prompt', injectRegister:false, workbox:{globPatterns, navigateFallback:'/index.html', navigateFallbackDenylist:[/^\/api\//], cleanupOutdatedCaches, runtimeCaching(NetworkOnly for /api/ + API origin RegExp)}})`. `UpdatePrompt.jsx` handles the update toast (read it to see how it registers the SW; the push subscription code must reuse `navigator.serviceWorker.ready`).
- Privacy greps already known: `OfferRide.jsx` line ~36 `whatsappNumber: user?.phone || ''` and required validation; `RideDetails.jsx` ~269 notice text mentions WhatsApp and ~337-347 `ride.whatsappLink` button ("Contact Driver on WhatsApp"); `Home.jsx` line 15 copy; `MyRides.jsx` ~300 tooltip "someone confirmed on WhatsApp"; `Register.jsx` collects phone ("WhatsApp Phone Number" label; keep field, rename label to "Phone Number (private)"). `Login.jsx` uses its own local `email` state only (fine).
- Tests live in `frontend\tests\*.test.js` as pure node:test files importing from `../src/utils/*.js` / `../src/lib/*.js` (no React/DOM). DECISION: put ALL testable logic in pure `.js` modules (no JSX) so node:test can import them. Component behaviour that cannot run under node:test is covered by pure helper tests plus `build` and `lint`, and noted as not browser-verified.
