- Auth: `POST /api/auth/register` {name,email,password,phone} → 201 `{success,data:{token,user:{id,name,email,phone,role}}}`; duplicate → 409; missing fields → 400. `POST /api/auth/login` → 200 same shape; bad creds → 401. `GET /api/auth/me` (protect) → 200 `{data:{user:{id,name,email,phone,role,createdAt}}}`; no header → 401 "no token provided"; bad token → 401. ## Design decisions

- **Backend tests: jest 30.5.2 + supertest 7.3.1 + mongodb-memory-server-core 11.3.0** (exact pins, devDependencies). Jest gives the familiar `describe/expect` evidence output judges recognise. The `-core` package is chosen over `mongodb-memory-server` because it has NO postinstall binary download, so Vercel/Render `npm install` of the backend is not slowed or broken; the MongoDB binary downloads on first `npm test` only (cached under `node_modules/.cache`).
- **App export for supertest:** add `process.env.NODE_ENV !== 'test'` to the existing listen condition. Jest sets `NODE_ENV=test`, so tests never open port 5000; every non-test runtime (local `node server.js`, nodemon, Render, Vercel) evaluates exactly as before. `module.exports = app` already exists.
- **Verified badge:** `updatedBy` already exists and is always set by admin-gated writes. Add an additive, computed `verified: boolean` to `GET /api/road-status` items (populate `updatedBy` with `role email`, true when role is 'admin' or email matches `ADMIN_EMAIL`). Author email/id are never emitted, so no privacy leak; sort code is untouched. Legacy records without `updatedBy` show no badge (honest default).
- **Frontend tests:** use Node's built-in runner (`node --test`) for the two pure util modules — zero new dependencies. Utils import siblings with explicit `.js` extensions so Node can run them.
- **Parser extras:** add an `'Islamabad'` landmark (aliases `islamabad`, `isb`; matches any Islamabad sector/landmark text) so "parso pindi se islamabad" yields a clean result instead of a leftover keyword that would wrongly exclude "Blue Area" rides. `parseCommuteQuery` accepts an optional `now` Date for deterministic tests and adds `hasTokens` to the documented return shape.
- **Feed date switching happens in the input `onChange` handler** (not an effect) so there are no set-state-in-effect loops and manual tab clicks still win afterwards. Plain queries with no detected tokens keep the exact old filter behaviour.
